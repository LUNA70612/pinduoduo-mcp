# 规格与价格

商品链接可以包含多个型号、包装或套餐。MCP 按完整规格组合核对 SKU 和参考价，客户端再根据用户需求判断型号及其他条件是否匹配。

## 完整规格

`spec_selection` 使用页面返回的真实规格组名和值，包含所有必选项：

```json
{
  "goods_id": "<搜索结果中的商品ID>",
  "spec_selection": {
    "<实际规格组名>": "<实际选项值>"
  },
  "budget_max": 200
}
```

以上为参数结构示例，组名和值从当前商品的 `spec_groups` 取得。多规格组需全部填写。

读取时依次核对当前商品、可见规格面板、规格组、选项值及唯一 SKU。定位使用商品和规格含义，选项数量与排列顺序不作为选择依据。

默认完整组合符合需求时可直接核验；指定其他组合时，通过已识别的可见规格控件选择。型号、版本、后缀、包装和套餐分别对应实际选项。

## 型号与参考价

| 核对项 | 依据 |
|---|---|
| 需求匹配 | 用户指定的型号、版本及其他硬条件 |
| 规格匹配 | 页面当前选中的完整组合及唯一 SKU |
| 价格核验 | 当前商品、选中摘要和稳定可见价格 |

两项结果分别返回和使用：客户端判断需求匹配，MCP 确认完整规格与价格关联。`variant_price_verified=true` 表示该具体组合的价格已经核对。

搜索显示价用于初筛，逐 SKU 的 `price_assessment.reference_price` 用于具体规格比较。`budget_max` 按单件规格商品价判断预算。

## 价格条件

| 字段或状态 | 用途 |
|---|---|
| `price_assessment.reference_price` | 完整规格的一件商品参考价 |
| `item_price_within_budget` | 商品价在预算内，其他费用单独说明 |
| `conditional_within_budget` | 附拼单或优惠等条件的价格在预算内 |
| `over_budget` | 已核验商品价超过预算 |
| `unknown` | 价格或预算依据尚未确定 |
| `total_price_confirmed` | 完整到手总价的确认状态 |
| `unit_price` | 根据明确净含量、包装数及规格参考价计算的单位价 |

普通拼单、优惠资格、促销和数量条件按页面原意保留。运费与其他费用分别说明，最终成交信息以平台结算页面为准。

## 页面数量与可选状态

| 字段 | 含义 |
|---|---|
| `available` | 页面来源中的在售或可用标记 |
| `stock` | 对应 SKU 的页面可售数量；没有明确数据时为 `null` |
| `selection_available` | 当前规格控件是否允许选择 |
| `unselectable_reason` | 控件不可选时的原因分类 |
| `stock_evidence` | 页面数量的归属与映射依据 |

`page_stock_zero` 表示控件禁用且页面数量证据为零；`disabled_control` 表示其他未确认数量原因的禁用状态。多套餐选项的数量按各组合分别核对，只有完整映射的所有组合都明确为零时，才归为选项级零数量。

页面数量、在售标记和控件状态分别使用。参考价、数量与规格始终关联当前商品，尚未确认的字段保留 `null` 或 `unknown`。
