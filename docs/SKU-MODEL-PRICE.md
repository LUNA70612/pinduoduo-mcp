# 型号、规格与参考价

同一商品链接可能包含多个型号、包装或套餐。商品标题和搜索显示价不能代替目标规格的核验结果。

## 两项核对

| 核对项 | 依据 | 负责方 |
|---|---|---|
| 型号是否符合需求 | 用户指定的型号、版本、后缀与页面真实完整规格 | 客户端AI |
| 该规格的价格是否已核验 | 当前商品、完整选择、唯一SKU关联及稳定可见价格 | MCP读取器 |

两项同时满足才可用于目标型号的推荐和预算比较。`variant_price_verified=true`只表示该组合的价格已核验，不表示它符合用户的所有需求。客户端指引通过三个购物模板及`initialize.instructions`提供，服务端不执行自然语言型号识别。

例如，用户需要5600GT时，同链接5500的价格不能作为5600GT参考价；标题含有5600GT，也不能证明默认选中的SKU就是5600GT。

## 读取流程

1. 在同一MCP连接内正常搜索，从真实搜索卡片进入商品。
2. 核对当前完整规格。默认组合已核价且符合需求时可直接使用。
3. 默认组合不符时，从真实`spec_groups`中核对目标型号和其他必选项，使用完整`spec_selection`请求该组合。返回的少量`skus`不代表全部规格。
4. 只有商品身份、当前选择、唯一SKU和稳定可见价格一致时，才确认该规格参考价。
5. 型号缺失、选项禁用、入口不明确或价格关联不足时，保留原因与未知项，不借用其他规格价格。

规格定位按当前商品、唯一可见面板、规格组及选项值逐级核对，不依赖固定序号。仅使用已识别的可见安全控件，不强点禁用选项，不执行购买或确认。

## 数量与禁用原因

| 字段 | 含义 |
|---|---|
| `available` | 页面来源中的在售/可用标记 |
| `stock` | 当前商品精确SKU的页面可售数量；缺失或无效时为`null` |
| `selection_available` | 当前控件是否允许选择 |
| `unselectable_reason=page_stock_zero` | 控件禁用，且有页面数量为0的证据 |
| `unselectable_reason=disabled_control` | 控件禁用，未确认是零数量所致 |

页面数量不等于仓库实物或全平台库存，在售标记也不证明控件可选。对于多套餐的规格选项，只有所有组合都有完整、唯一映射且数量均明确为0时，才提供选项级零数量证据；单个套餐为0不能推广为整个型号无货。

禁用请求保留`spec_option_disabled`等原始诊断，不确认目标价格。数量不明时，不从限购数、初始数量或在售标记推断库存。

## 验证范围

- 本地回归覆盖混型号、长列表、多规格组、重复或禁用选项、异步价格、点击未更新和商品身份异常。
- 同类CPU页面已验证默认型号不符、目标型号缺失，以及单型号完整组合的参考价核验。
- 数量诊断在混型号商品上分别通过stdio和HTTP核对；禁用目标的负向验证确认没有切换选择或返回已核验价格。
- 多套餐数量归因由脱敏fixture回归覆盖。模拟布局和测试价格用于验证逻辑，不作为真实商品报价或全模板兼容证明。

不同记录保留各自版本、读取时间和运行文件哈希；已有默认组合核价与成功切换非默认组合分别计数。验证方法见[测试说明](../TESTING.md)，当前兼容范围见[能力说明](../CAPABILITIES.md)。
